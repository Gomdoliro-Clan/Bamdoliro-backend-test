# 백엔드 인턴 과제

입학처 서비스(마루)에서 실제로 겪은 문제를 바탕으로 만든 과제입니다.
새로운 기능을 만드는 과제가 아니라 코드를 읽고, 문제를 찾아 고치고, 왜 그런지 설명하는 과제입니다.
정답을 맞히는 것보다 어떻게 생각했는지를 더 중요하게 봅니다.

## 진행 방법

1. 이 레포를 포크합니다. 포크한 레포는 비공개로 두고, 안내받은 사람만 볼 수 있게 합니다.
2. 로컬에 받아서 작업합니다. 필요한 것은 JDK 17 이상뿐입니다. 데이터베이스, Docker, 외부 서비스는 필요 없습니다.
3. 작업이 끝나면 포크한 레포의 주소를 안내받은 방법으로 제출합니다.

```
./gradlew test
```

처음 실행하면 실패하는 테스트가 있는 것이 정상입니다. 그 테스트가 풀어야 할 문제입니다.

## 구성과 배점

| 파트 | 내용 | 배점 |
| --- | --- | --- |
| 파트 1 | 버그 5개 찾아서 고치고 원인 설명 | 40 |
| 파트 2 | 실제 서비스 코드를 읽고 서술형 답변 6문항 | 30 |
| 파트 3 | 선발 로직 구현 1문항, 번호 발급 설계 1문항 | 30 |


## 규칙

- `src/test` 아래의 기존 테스트 파일은 수정하지 않습니다. 테스트를 추가하는 것은 자유입니다.
- JUnit 외의 라이브러리를 추가하지 않습니다.
- 답변은 모두 `ANSWERS.md`에 작성합니다. 코드를 고쳤더라도 설명이 없으면 점수가 깎입니다.
- 커밋은 문제 단위로 나눠 주세요. 커밋 메시지는 무엇을 왜 바꿨는지 알 수 있게 씁니다.
- AI 도구를 사용해도 됩니다. 다만 사용한 도구와 용도를 `ANSWERS.md` 맨 아래에 반드시 적고, 제출한 코드와 답변은 면접에서 직접 설명할 수 있어야 합니다.
- `materials/` 폴더의 코드는 실제 서비스에서 발췌한 것입니다. 이 과제 외의 용도로 사용하거나 외부에 공유하지 않습니다.

## 파트 1. 버그 찾기

`src/main` 에는 원서를 임시저장하고 제출하는 작은 서비스가 있습니다. 데이터베이스와 외부 저장소는 모두 메모리에서 흉내 낸 것입니다.
`src/test/java/com/bamdoliro/assessment/part1` 의 테스트 5개 묶음이 각각 하나의 문제입니다. 테스트가 실패하는 이유를 찾아 고칩니다.

- 문제 1. StatusTransitionTest: 원서 상태 전이
- 문제 2. SubmitErrorHandlingTest: 제출이 실패했는데 성공처럼 보임
- 문제 3. TrackValidationTest: 잘못된 입력에 대한 응답
- 문제 4. ConcurrentSubmitTest: 동시 요청
- 문제 5. ListQueryTest: 목록 조회

이미 통과하는 테스트는 계속 통과해야 합니다. 테스트를 통과시키는 것이 목표가 아니라, 원인을 이해하고 알맞게 고치는 것이 목표입니다.

원서 상태 전이 규칙은 다음과 같습니다.

| 현재 상태 | 이동 가능한 상태 |
| --- | --- |
| DRAFT | SUBMITTED |
| SUBMITTED | FIRST_PASSED, REJECTED |
| FIRST_PASSED | FINAL_PASSED, REJECTED |
| REJECTED | 없음 |
| FINAL_PASSED | 없음 |

DRAFT 상태에서만 원서를 수정할 수 있습니다. 같은 원서를 두 번째로 제출하면 `ALREADY_SUBMITTED` 로 거절합니다.
잘못된 요청은 4xx, 서버 내부 문제는 5xx 로 응답합니다.

## 파트 2. 코드 읽고 답하기

`materials/07-issues.md` 의 이슈 요약과 `materials/` 의 코드를 읽고 `ANSWERS.md` 에 답합니다. 코드는 실제 서비스에서 발췌한 것이며, 각 문항이 가리키는 파일을 확인하세요.
문항마다 3~8줄 정도면 충분합니다. 조건에 따라 답이 달라진다면 그 조건을 적어 주세요.

## 파트 3. 문제풀이

### 3-1. 1차 선발 구현

`SelectionAlgorithm.select` 를 구현합니다. 실제 서비스의 1차 선발 로직(`materials/05-...`)을 단순화한 문제이며, 아래 규칙만으로 구현할 수 있습니다. `materials` 의 코드를 보지 않고 풀어도 됩니다.

1. 지원자를 점수 내림차순으로 정렬합니다. 점수가 같으면 접수번호 오름차순입니다. 입력 목록은 수정하지 않습니다.
2. 정렬된 순서대로 한 명씩 봅니다. 아직 정원이 남아 있는 동안은 다음과 같이 처리합니다.
   - 부산 지원자는 합격하고 정원이 1 줄어듭니다.
   - 부산 외 지원자는 부산 외 한도가 남아 있으면 합격하고, 한도와 정원이 각각 1씩 줄어듭니다. 한도가 없으면 불합격이며 정원은 줄어들지 않습니다.
3. 정원이 모두 찬 뒤에는 정원 순번 점수와 같은 점수를 받은 지원자만 합격하고 나머지는 불합격입니다. 이때 지역은 보지 않습니다.
4. 정원 순번 점수는 정렬된 전체 목록에서 `min(정원, 전체 인원)` 번째 지원자의 점수입니다.
5. 정원이 0 이하이면 전원 불합격입니다. 지원자가 없으면 빈 결과를 돌려줍니다.

공개된 테스트 외에 경계 조건을 다루는 추가 테스트로 채점합니다. 스스로 테스트를 더 만들어 보세요.

### 3-2. 수험번호 발급 설계

코드는 작성하지 않고 `ANSWERS.md` 에 설계를 서술합니다. 자세한 내용은 `ANSWERS.md` 를 보세요.
